# Взвешенный Joint: модель, реализация, пределы выводов

## Что именно модифицируется

OCP-FL определяет проверяемый roster и разрешения; Joint выбирает один/два коллектора для текущего roster и proof-окна. Исходный Joint — факторизованный табличный one-hot оцениватель путей с оптимистическим бонусом и primal-dual штрафами. Это **не** буквальный disjoint линейный Article PD, который обучается на round-level reward. Названия D-LinUCB/SW-LinUCB обозначают научные источники механизмов, а не тождество всей системы этим алгоритмам.

Для ячейки ℓ=(worker, gateway, window) и действия в слоте s:

* D_sℓ — немедленно известная booked geometry;
* O_sℓ(t) — метка этой ячейки уже доставлена к решению t и допустима по выбранному feedback rule;
* Y_sℓ∈{0,1} — своевременное валидное proof-сообщение;
* неизвестный или неисполненный путь не получает отрицательной метки;
* после созревания неизвестная booked geometry удаляется из обучения, но ресурсный расход остаётся.

В исходном классе вне собственного окна design добавляется при известной метке. В memory-реализации это эквивалентно переходу pending → known/unknown при доставке. Никакая метка из будущего не используется.

## Два механизма памяти

Индексы слотов начинаются с 0. Перед выбором t сохраняются:

`w_ts = γ^(t−s)` для discount, 0<γ≤1;

`w_ts = 1{t−W ≤ s < t}` для окна, W≥1.

Возраст определяется **моментом генерации действия s**, не временем доставки. Метка старого действия, пришедшая поздно, имеет старый вес; если s уже вышел из окна, она не возвращает удалённую статистику. Код не получает времени переключения CPU-нагрузки и не делает oracle-reset на раунде 40.

С учётом актуальной известности/геометрии ячейки:

```
n_tℓ = Σ_s w_ts D_sℓ(t)
m_tℓ = Σ_s w_ts O_sℓ(t)
z_tℓ = Σ_s w_ts O_sℓ(t) Y_sℓ
q_tℓ = Σ_s w_ts² D_sℓ(t)
v_tℓ = Σ_s w_ts² O_sℓ(t)
p_hat_tℓ = 1/2 + (z_tℓ − m_tℓ/2)/(ρ+n_tℓ)
b_tℓ = α sqrt(ρ+q_tℓ)/(ρ+n_tℓ)
```

Постоянная ridge ρ не забывается. Pending observations остаются центрированными на 1/2 до доставки, как в исходном design-now/label-later. В журнале есть n,m,v, effective labels `m²/v` (0 при v=0), weighted mean age и pending mass n−m. Суммарная геометрия намеренно включает pending; поэтому радиус отдельно **не покрывает** смещение из-за недоставленных меток. Альтернатива полностью выкинуть pending из знаменателя изменила бы алгоритм; в этой версии она не вводится скрыто.

Для дисконтирования при сдвиге на один слот:

```
n ← γn; m ← γm; z ← γz
q ← γ²q; v ← γ²v
age_mass ← γ(age_mass + m_old)
```

При доставке в t удаляется weighted pending-вклад исходного s и добавляется известный weighted-вклад того же s, с квадратом веса для второго момента. Для окна очередь хранит вклад последних W слотов и удаляет его при s<t−W. Работа основного discounted обновления пропорциональна числу ячеек и созревшим меткам, без хранения всей истории. Window дополнительно хранит O(W×число затронутых ячеек) вкладов; очередь недоставленных меток зависит от feedback delay. Истёкшие window-events очищают обучающие entries, сохраняя только необходимую ссылку до созревания.

При γ=1 либо W≥H и legacy feedback действия, статистики и цены совпадают с исходным Joint с численной точностью; это проверено регрессией. При w∈{0,1} q=n, и новый бонус совпадает с α/√(ρ+n). Для discount отдельно доступен `joint_discounted_legacy_bonus`: та же память, старый радиус, чтобы изолировать геометрию бонуса.

## Почему квадрат весов обязателен и чего он не доказывает

У взвешенной регрессии с независимым шумом ковариационная геометрия содержит сумму **квадратов** весов. В one-hot ячейке `V=ρ+n`, `V_tilde=ρ+q`, поэтому `sqrt(xᵀV⁻¹V_tilde V⁻¹x)=sqrt(ρ+q)/(ρ+n)`. Это соответствует структуре D-LinUCB у [Russac, Vernade, Cappé, NeurIPS 2019](https://proceedings.neurips.cc/paper/2019/hash/263fc48aae39f219b4c71d9d4bb4aed2-Abstract.html). Простая подстановка discounted n в старый радиус не воспроизводит эту структуру.

**α в реализации не является калиброванной β_t(δ).** Нет заявленной 95%-границы или regret-теоремы. Для настоящей границы нужны условия на шум, норму параметра, предсказуемость отбора и соответствующая self-normalized β. Кроме стохастического члена, текущая ошибка включает:

* ridge-bias (в центрированной Bernoulli-модели до ρ/[2(ρ+n)]);
* pending-label bias (при обозначенных предпосылках до pending_mass/[2(ρ+n)]);
* drift-bias, пропорциональный weighted sum `Σ w |p_sℓ−p_tℓ|/(ρ+n)` для известных меток;
* селективное цензурирование/ошибку спецификации, если используется legacy перенос между окнами.

Один только бонус не покрывает эти члены. Независимые метки в пути не делают независимыми пути и workers. Доказательство для линейной награды нельзя перенести на произведение неизвестных вероятностей, delayed/censored observations, отбор действий и несколько бюджетов без новой теории.

Sliding-window механизм опирается на [Cheung, Simchi-Levi, Zhu, AISTATS 2019](https://proceedings.mlr.press/v89/cheung19b.html). Малое W ускоряет забывание, но увеличивает дисперсию в 48 разреженных ячейках (4 workers ×4 gateways ×3 окна в текущем стенде). При W=16 меток на часть ячеек может вообще не оказаться; это измеряется, а не трактуется как гарантия адаптации. γ=.95 соответствует масштабу памяти около 20 слотов, но effective N зависит от посещений и задержки.

## Частичная и задержанная обратная связь

`legacy` сохраняет семантику v0.7.0: при положительном RTT метки выводятся для всех порогов; отрицательный результат известен только для порогов не больше исходного окна. Это обеспечивает честную memory-only абляцию, но наследует positive-only bias при переносе в длинные окна.

Отдельный `eligible` требует:

`O_sℓ = attempted_sℓ × 1{d_ℓ ≤ actual_observation_horizon_s} × delivered_s(t)`.

Eligibility для всех целевых порогов не зависит от успешности текущего отклика. RTT используется только после этой проверки. Полученный положительный RTT не разрешает включить удачный короткий опыт в оценку длинного окна. Новая общая точка начала RTT/фазы позволяет отличить точно номинальное окно от реально усечённого deadline. Неисполненные projections, неизвестные пути и раунды с byte-admission denial не превращаются в отрицательные route-labels. Время получения и маски сохраняются для причинной реконструкции. Existing results и их семантика не переписываются.

`Article PD` по-прежнему получает только свой delayed round reward, без привилегированного полного path-feedback. OCP roster, текущий контекст, общий delay и внешний hard feasible set одинаковы; различие гранулярности обратной связи указано явно как различие алгоритмов.

Eligible устраняет конкретный positive-only перенос между окнами, но не доказывает независимость всех пропусков от исходов. Сам факт неисполнения/байтового отказа может зависеть от ранее выбранных действий, очередей и объёма сообщений. Консервативное исключение такого раунда не равно теореме о несмещённости при произвольном missingness. Эти маски журналируются; модель процесса пропусков остаётся отдельным ограничением.

## Выбор действия и ресурсы

Для текущего roster R_t и выбранного множества A (один/два коллектора) остаётся исходная факторизация:

```
q_hat_t(A) = ∏_{i∈R_t} [1 − ∏_{g∈A}(1 − min(1,p_hat_tig+b_tig))]
a_t ∈ argmax_{A∈F_t} q_hat_t(A) − λ_t 1{|A|=2} − Σ_{g∈A} μ_tg
```

F_t исключает превышение оставшихся M и C_g. Byte ledger выполняет отдельный атомарный допуск реальных сообщений. Память влияет только на статистику предсказаний, не на F_t.

Целевые скорости вычисляются до списания:

```
r_t^M = (M−spent_before)/(H−t)
r_tg^C = (C_g−site_spent_before_g)/(H−t)
λ_{t+1} = max(0, λ_t + η(1{|A|=2}−r_t^M))
μ_{t+1,g} = max(0, μ_tg + η(1{g∈A}−r_tg^C))
```

Ни spent, ни квоты, ни λ/μ **не дисконтируются и не сбрасываются при смене среды**. Отказ proof или поздняя метка не возвращают разрешение и не создают новый бюджет. Это проверено, в том числе при истечении window и потере меток. Выбранные источники квот, delay и masked feedback сохраняются в frozen plan.

Даже идеальные текущие вероятности не решают оптимальное распределение конечного бюджета по неизвестному будущему. [Liu, Jiang, Li, NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/69469da823348084ca8933368ecbf676-Abstract-Conference.html) показывают, что обычной variation budget недостаточно для общей задачи nonstationary BwK; нужна дополнительная характеристика глобальной нестационарности. Их LP/primal-dual анализ не является доказательством оптимальности данного pacing-rule. Поэтому новая реализация — проверяемая адаптация памяти с явными ограничениями, а не «нестационарный primal-dual contextual bandit с доказанным преимуществом».

Без независимости допустимые вероятности объединения одного worker находятся между max p_g и min(1,Σp_g); для полного покрытия workers — между max(0,Σq_i−k+1) и min q_i. Продукт — дополнительное модельное предположение, не универсальная граница. Положительный результат в shared-host тесте не доказывал бы его истинность.
