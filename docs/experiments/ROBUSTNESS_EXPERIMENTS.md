# Границы результата: телеметрия и инициализация модели

## Протокол до просмотра TCP-результатов

Планировщики не меняются относительно динамической серии. Сравниваются
network_online и тот же network_prior с отключённым обновлением статистики.
Параметры priors, exploration и scoring остаются прежними.

Единственный первичный контраст: **network_online − network_prior в stale_noise**.
Отрицательная разность означает меньшее T_epsilon у обучаемого планировщика.
Остальные сравнения описательные, без поправки на множественные проверки.
Bootstrap среднего по полным парам: 20000 выборок, seed 163026.
Мощность заранее не оценивалась. Цензурированные времена не подменяются последним
наблюдением; bootstrap полных пар может быть смещён при недостижении порога.

## Сеть и причинный датчик

Истинные edge_limited/verifier_limited меняются после 4–8 попыток.
Общий предел соответствующего потока 40 MB/s, задержка сообщения 2 ms.
Все режимы датчика получают одну физическую трассу и отказы в данном повторе.
Меняется только информация, которую получает планировщик.

| Режим | Задержка | Логнормальный шум σ |
|---|---:|---:|
| exact | 0 попыток | 0 |
| noise | 0 попыток | 0.35 |
| stale | 2 попытки | 0 |
| stale_noise | 2 попытки | 0.35 |

Множитель exp(σZ−σ²/2) сохраняет среднее до защитного clipping. Полосы
ограничиваются [1;10000] MB/s, задержка [0.001;10000] ms, экспонента [−20;20].
Нулевой флаг «неограниченный поток» сохраняется: шум возмущает величину,
а задержка может сообщать о прежнем узком канале. Ошибки нулевого флага не моделируются.

Отчёт сначала захватывается, затем доставляется из уже захваченного префикса.
Пока задержанный канал заполняется, повторяется первый калибровочный отчёт.
Старый шум при доставке не генерируется заново. Псевдослучайные числа одинаковы
между режимами и стратегиями. Это синтетические ошибки, не реальные сетевые пробы.

## Инициализации и шаг обучения

Центральная диагностика без TCP сравнивает learning rate 1.0 и 0.5:
development seeds 0…7, validation seeds 16…23, до 120 обновлений.
До её результатов для новой серии задан консервативный шаг 0.5.
При 1.0 порог достигнут в 7/8 и 5/8 случаях; при 0.5 — 8/8 обеих групп.
Медианы успешных шагов среди достигших: development 30/64.5,
validation 30/69.5 для 1.0/0.5 соответственно.

Все заранее заданные модели 16…23 включены в TCP-серию: удобные seed не выбираются,
градиенты не обрезаются. Новые абсолютные времена не сравниваются напрямую
с прежней одной моделью 2026 при шаге 1.0. Старое значение 1.0 сохранено по умолчанию.

## Основная серия

12 участников, 50260 параметров, target loss 0.22. Восемь повторов, модели 16…23.
Четыре режима × два планировщика × восемь повторов = 64 запуска.
Дополнительно восемь фактических запусков F+P — по одному общему контролю
на модель/физическую трассу. Всего **72 запуска**. Сырые записи контроля не дублируются.
F+P выбран по прошлым независимым сериям и не использует датчик.
Сравнения с общим контролем коррелированы и не считаются независимыми.

Девять случаев в каждом повторе перемешиваются. Seed 63026+r: отказы +1000,
профили +2000, датчик +3000, planner +11000, порядок +20000.
До 160 попыток, deadline 1.5 s, RPC timeout 1.2 s, switching wait 0.025 s.

Результаты: новые каталоги, JSONL каждой попытки, CSV, metadata и source snapshot.
Анализ воспроизводит отчёты датчика, их источник/возраст, модель и learning rate.
Физическая передача, криптопроверки и обучение выполняются в общем TCP-runtime.

## Ограничения

Один Mac, прикладной pacing. Нет WAN, реальных измерительных проб, потери отчётов,
смены полосы посреди кадра и асинхронных градиентов. Задержка измеряется попытками,
не секундами. Восемь инициализаций одной архитектуры не доказывают общей сходимости.

## Завершённая проверка 27 октября 2026

Все 72 запуска достигли loss≤0.22; 6496 реальных раундов, 5157 принятых обновлений, без тайм-аутов. Пройдено 60 тестов. Данные: results/tcp_telemetry_robustness_20261027T132716Z_7ca6c222/.

Парная средняя разность network_online−network_prior, секунды:

| Условие | Разность | Описательный bootstrap 95% |
|---|---:|---:|
| exact | -0.384 | [-0.795; -0.045] |
| noise | -0.445 | [-0.760; -0.172] |
| stale | +1.278 | [+0.791; +1.707] |
| stale_noise | +0.824 | [+0.344; +1.313] |

Первичное условие stale_noise показало отрицательный результат для обучения: интервал разности положителен, online медленнее prior. Только шум без задержки не разрушил наблюдённый выигрыш в этой выборке. Вторичные интервалы не скорректированы за множественные сравнения.

Код текущего планировщика не получает возраст отчёта и вычитает оценку передачи, построенную по доставленным сведениям, при обновлении среднего остаточного времени. Проверка варианта, учитывающего возраст, в эту серию не входила. Это обнаруженная граница применимости метода, не основание менять или исключать отрицательные результаты.
