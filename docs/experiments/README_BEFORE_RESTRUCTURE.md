Исследовательский стенд онлайн-выбора размещения и проверки агрегации.
Новый `tcp_closed_loop_pilot.py` выполняет **настоящее обучение через TCP на localhost**:
отдельный процесс каждого участника, четыре edge-процесса и проверяющий в основном процессе.
Это проверка реализации на одном компьютере, а не измерение распределённой WAN/edge-сети.

Продолжение: добавлены общие для процессов ограничения передачи и отдельная
серия сравнения сетевых режимов. Команды и точные допущения — в
[NETWORK_EXPERIMENTS.md](NETWORK_EXPERIMENTS.md). Профиль по умолчанию `unlimited`
сохраняет исходный режим без ограничения. Результаты версии 1 сохранены отдельно.

Динамическое продолжение, где ограниченный поток меняется между раундами:
[DYNAMIC_EXPERIMENTS.md](DYNAMIC_EXPERIMENTS.md). Основной протокол сравнения
задан до основной серии; будущая трасса планировщику недоступна.

Проверка границ результата — [ROBUSTNESS_EXPERIMENTS.md](ROBUSTNESS_EXPERIMENTS.md):
причинная шумная/запаздывающая телеметрия и разные начальные веса MLP.

## Установка и быстрый запуск

Проверено на macOS Apple Silicon с Python 3.13.7. Из каталога проекта:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tcp_closed_loop_pilot.py --config configs/tcp_smoke.json
```

Существующую `.venv` пересоздавать не нужно. В PyCharm выберите её интерпретатор,
скрипт `tcp_closed_loop_pilot.py`, рабочую директорию проекта и аргументы
`--config configs/tcp_smoke.json`. Скрипт должен запускаться как файл: `spawn`
не предназначен для запуска этого эксперимента через интерактивный `python -c`.

Постепенное масштабирование:

```bash
.venv/bin/python tcp_closed_loop_pilot.py --config configs/tcp_smoke.json --workers 4
.venv/bin/python tcp_closed_loop_pilot.py --config configs/tcp_smoke.json --workers 8
.venv/bin/python tcp_closed_loop_pilot.py --config configs/tcp_smoke.json --workers 12
```

Пять раундов — проверка программного пути; порог loss 0.22 за них обычно не достигается.
Для измерения времени достижения качества:

```bash
.venv/bin/python tcp_closed_loop_pilot.py --workers 12 --rounds 80 --repeats 6 --scenario faults
.venv/bin/python tcp_closed_loop_pilot.py --config configs/tcp_full.json
```

Полная конфигурация задаёт 20 повторов, 4/8/12 участников, 6 стратегий, до 100 попыток,
порог 0.22 и независимый от smoke-тестов базовый seed 12026. Сценарий повтора r
использует seed 13026+r, планировщик 22026+r, порядок стратегий 32026+r. `model_seed=2026`
отдельно фиксирует исходную модель исторического эксперимента. Полный запуск может занять заметное время.
Это заранее заданный протокол эксперимента, а не обещание статистической мощности.
Параметры командной строки перекрывают JSON. `--help` показывает остальные настройки.
`--output` должен указывать **новую** директорию: перезапись результатов запрещена кодом.

## Полный раунд

1. Стратегия выбирает `F+B`, `F+P`, `R+B` или `R+P` до получения результата раунда.
2. Проверяющий передаёт текущие параметры MLP участникам. Каждый процесс вычисляет
   настоящий градиент на своей части Digits, взвешивает его по числу примеров и квантует.
   Используются методы `MLP.gradient/update/score` из `training_experiment.py`.
3. Двенадцать блоков, включая блоки неравной длины, образуют две полосы по чётности
   номера блока. В F они назначены edge 0/1; в R также edge 2/3.
4. Edge-процессы **напрямую по TCP** запрашивают свои фрагменты у участников и складывают их.
5. Проверяющий собирает кандидат только из edge-ответов и применяет выбранную проверку.
6. Проверенный кандидат обновляет модель только до дедлайна. При истечении дедлайна
   во время применения обновления параметры восстанавливаются.

**B:** участники передают подписанные полные обновления вместе с ответом на вычисление.
Проверяющий сохраняет их, проверяет Ed25519 и пересчитывает сумму для сравнения с кандидатом.
Поэтому исчезновение участника *после доставки подписанного обновления и фрагментов*
не мешает B. Время и байты ранней передачи включены в раунд.

**P:** ответ на вычисление содержит только метрики. Проверяющий не получает исходные
обновления. После фиксации кандидата он генерирует два независимых криптографически
случайных seed, участники подписывают проекции своих текущих обновлений, затем проверяющий
сравнивает проекции в поле. Нужны ответы **всех** участников.

R дожидается всех запущенных реплик либо их тайм-аутов, сортирует комбинации по наблюдённому
времени и проверяет до четырёх различных кандидатов. Повторный идентичный кандидат пропускается.
Каждая новая проверка P получает новый вызов. Все повторы входят в время и трафик.
Резерв не гарантирует восстановление: нужна корректная копия каждой полосы, ответы участников
для P и достаточное оставшееся время. Ожидание медленной резервной копии — известная цена
этой простой реализации; отмена лишних реплик и проверка до прихода всех копий пока не реализованы.

## Протокол и безопасность

`tcp_transport.py`: ограниченные длины заголовка/данных, JSON без повторных ключей,
явный little-endian формат векторов, HMAC-SHA256 с отдельными ключами каждой пары процессов,
идентификаторы отправителя/получателя/сессии/эпохи/раунда и nonce запроса.
Ответ должен соответствовать запросу. Повторный nonce, старый раунд, неверная подпись,
неизвестный отправитель и неполный набор ответов отклоняются.
Ключи передаёт доверенный локальный launcher через `spawn` IPC; Ed25519-ключ создаётся
в процессе участника, проверяющий получает только публичный ключ.
TCP привязан к `127.0.0.1`. Конфиденциальность, PKI и развёртывание между компьютерами
потребуют отдельного транспорта, например взаимно аутентифицированного TLS.

Модель угроз: честные участники и проверяющий, неисправные/недобросовестные агрегаторы.
Корректность самих градиентов, сговор участников с агрегатором и защита от исчерпания
ресурсов публичным сетевым противником не доказываются.

Поле P = 2³¹−1. Каждый целочисленный градиент ограничен по модулю 200000;
для n участников требуется `2*n*MAX_UPDATE < P`. Поэтому две разные допустимые суммы
не становятся одним вектором по модулю P. Произведения суммируются безопасными блоками,
baseline проверяет предел до сложения в int64. Некорректные значения отклоняются,
а не обрезаются. Проекции не являются универсальным доказательством вычислений.

При выходе обновления за границу стратегия останавливается с
`stop_reason=update_out_of_range`: повтор вычисления на той же модели не исправит
детерминированную ошибку. Это недостижение порога, а не принятый результат или
скрытое ограничение градиента. Начальные веса меняются через `--model-seed` независимо
от `--seed` сценария и планировщика. Существующий learning rate равен 1.0; он не
гарантирует устойчивое обучение для любой инициализации. В частности, при seed модели
12026 обнаружена дивергенция, сохранённая как отдельный отрицательный результат.

Для фиксированной ненулевой ошибки d и **идеально независимых равномерных** весов r
вероятность `dot(d,r)=0` равна 1/P: условившись на остальных координатах, единственный
коэффициент при ненулевой координате d задаёт ровно одно подходящее значение r.
Две независимые проверки дают P⁻² ≈ 2.17×10⁻¹⁹ на кандидат; до четырёх кандидатов —
не более 4/P² по union bound. Реализация разворачивает seed через SHAKE256 с rejection
sampling, поэтому эта оценка относится к идеализированной модели XOF и дополняется
вычислительными предположениями о SHAKE256, SHA256 и неподделываемости Ed25519.
Это аналитическая оценка, не измеренная частота ошибок.
Описание принципа случайных проверок: [лекции Justin Thaler](https://people.cs.georgetown.edu/jthaler/fingerprinting.pdf).
API подписей: [официальная документация cryptography](https://cryptography.io/en/stable/hazmat/primitives/asymmetric/ed25519/).

## Измерения

Каждый запуск создаёт новую `results/tcp_closed_loop_<UTC>_<id>/`:

- `metadata.json`: параметры, версии, платформа, хеши исходников и статус завершения.
- `scenario_*.json`: сценарий каждой пары условий, заданный до выбора действий.
- `rounds.csv` и отдельные `rounds_w*_r*_*.csv`: исходные измерения каждого раунда.
- `summary.csv`: достижение порога, T_epsilon, успехи, трафик, переключения, отклонения.
- `paired.csv`: разности online − каждая фиксированная стратегия/правило на парных повторах.
- `learning_wall_clock.png`, `time_to_quality.png`: физическое время localhost, явно подписанное.

Определения времени:

| Поле | Что измерено |
|---|---|
| `t_epsilon_wall_s` | Непрерывное физическое время от начала обучения после прогрева до завершения validation, впервые подтвердившей порог |
| `round_wall_s` | От начала выбранного раунда, включая переключение, до принятия/отклонения и применения обновления |
| `cycle_wall_s` | Выбор действия + раунд + validation + сбор телеметрии |
| `gradient_max_s` | Максимум длительностей градиентов отдельных участников; вычисления параллельны |
| `gradient_cpu_sum_s` | Сумма `thread_time()` вычислявших градиенты потоков при одном BLAS-потоке |
| `worker_rpc_wall_s` | Параллельная стадия передачи модели, вычислений и получения ответов; B включает полные подписанные обновления |
| `update_fetch_max_s` | Максимальная длительность получения фрагментов на edge, включая RPC и ожидания |
| `edge_compute_max_s`, `edge_cpu_sum_s` | Только сложение фрагментов на edge: максимум wall-time и сумма CPU-time |
| `edge_rpc_wall_s` | Получение всех запущенных edge-ответов или тайм-аутов |
| `proof_prepare_max_s`, `proof_prepare_cpu_sum_s` | Подготовка подписей/проекций на участниках; максимум wall и сумма CPU по всем попыткам |
| `projection_rpc_wall_s` | Получение ответов проекций по TCP, включая подготовку и ожидания |
| `verification_wall_s`, `verification_cpu_s` | Проверка на координаторе, включая повторные кандидаты; без ожидания ответов P |
| `*_send_sum_s` | Суммарное время блокирующих socket.send: может перекрываться между процессами и не равно чистой сетевой задержке |
| `serialization_wall_sum_s` | Сумма времени сериализации/разбора/аутентификации кадров по процессам |
| `child_peak_rss_sum_bytes` | Сумма индивидуальных максимумов RSS дочерних процессов; не одновременная RSS и не уникальные физические страницы |

`update_transfer_*` относится к worker→edge, `aggregate_transfer_*` — к edge→проверяющему,
`worker_compute_reply_*` включает полный вектор для B. `model_broadcast_*` и `proof_transfer_*`
показывают остальные большие потоки. `app_tx_bytes` считает каждый отправленный байт
прикладного кадра один раз по всем процессам; TCP/IP, ACK и служебные запросы телеметрии
с round=0 исключены. В корректном завершённом раунде проверяется совпадение tx и rx.
При тайм-ауте/потере процесса счётчик может не включить позднюю отправку или статистику
погибшего процесса; `traffic_is_lower_bound=1` отмечает это ограничение.

**Перекрывающиеся интервалы нельзя складывать в полное время раунда.** Полное время
измеряется отдельно. Односторонняя задержка сети не извлекается вычитанием CPU из RPC:
буферизация, сериализация и ожидания перекрываются. WAN-формул и старых TCP-калибровок
в новом пути нет. `switch_seconds` — реально выполняемое, но искусственно заданное
ожидание переключения, а не измеренная стоимость реальной реконфигурации.
`--traffic-budget-mb` останавливает запуск после раунда, достигшего бюджета;
это порог остановки с возможным превышением на один раунд, не строгий сетевой лимитер.

Запуск процессов, подготовка датасета, начальная validation и один одинаковый прогрев
F+B перед каждой стратегией исключены из T_epsilon; startup записан отдельно.
В T_epsilon входят выбор действий, предыдущая validation, телеметрия и сбор строк результатов
между раундами. Телеметрия после последнего достижения порога не входит в T_epsilon.
CSV сохраняется после каждой стратегии; внезапное завершение ОС может потерять текущую
ещё не завершённую стратегию. При обычной ошибке/KeyboardInterrupt процессы очищаются.

## Сравнение стратегий

`rule` использует только прошлый успех/задержку и число участников. При прошлой ошибке
или длительном раунде включает резерв; для n≥12 предпочитает P, если прошлый P не отказал.
Это явная простая эвристика, не oracle.

`online` — базовый контекстный bandit: четыре начальных пробных действия, затем оценка
успехов в единицу времени и 8% исследования. Контекст — только прошлые наблюдения.
Обновляется статистика **только выбранного действия**. Из наблюдённой длительности
вычитается измеренное ожидание переключения; при выборе стоимость следующего переключения
добавляется один раз. Алгоритм не получает `Fault` и результаты невыбранных действий.

В каждой паре одинаковы начальная модель, данные, целевой loss и сценарий по номеру попытки.
Порядок стратегий перемешивается отдельно от генератора сценариев и планировщика.
Физическое расписание ОС и задержки localhost не детерминированы. Seed фиксирует данные,
сценарий и решения при одинаковой обратной связи, но не времена и не решения, зависящие
от измеренных времён. Криптографическая случайность всегда берётся из ОС.

`faults` включает управляемые ответы об отказе primary-площадки, подмену edge-результата,
недоступность участника в P и реальные ожидания .03 s на загруженных primary-узлах.
Это воспроизводимая инъекция на localhost, не реконструкция реальной edge-сети.
Настоящее завершение процесса и отсутствие TCP-ответа дополнительно проверяются тестами.
Сценарии привязаны к номеру попытки, а не глобальному wall-clock; стратегии проходят
разное число попыток до порога. Одинаковый seed не устраняет влияние ОС, температуры и кэшей.

Недостигнутый порог имеет пустой `t_epsilon_wall_s` и `reached=0`. Нельзя заменять его
временем последнего раунда. Bootstrap-интервалы в `paired.csv` описательные, по **полным
парам**; они не исправляют смещение от недостижения порога и множественных сравнений.
Всегда сообщайте долю достигших порога. Малое число повторов не доказывает преимущество
алгоритма; до подтверждающего исследования нужен расчёт мощности/заранее выбранный контраст.

## Исторические эксперименты

`joint_planning_experiment.py` использует заранее вычисленную траекторию обучения и модель
сети. `closed_loop_joint.py` пересчитывает градиенты в каждом раунде, но по-прежнему
моделирует сеть и использует старую калибровку TCP. Их цифры не являются T_epsilon
физического распределённого обучения. Их CSV сохранены без изменения.

`tcp_process_experiment.py` измеряет только проверку заранее известных обновлений,
без настоящего обучения и edge-процессов. Подробный аудит — `AUDIT.md`.

## Ограничения и следующий этап

Четыре edge-процесса объединяют двенадцать блоков в две полосы; восстановление работает
при корректной копии каждой полосы. Процессы используют ограниченные RPC и `spawn`;
при закрытии сначала посылается stop, затем join, terminate и kill при необходимости.
Процессы участника живут между раундами; BLAS ограничен одним потоком на процесс.
Сбой ОС, нативной библиотеки или всего хоста не моделируется как штатный сетевой отказ.

При нехватке памяти используйте отдельные запуски для каждого числа участников,
меньшую сеть через `--hidden` для диагностики либо управляемый пул. Пул меняет степень
параллелизма и требует отдельной серии результатов. Для вывода о распределённой сети
нужны несколько машин, аутентифицированный транспорт, независимое управление каналами
и измерение времени с единой точки координатора. Их результаты нельзя смешивать
с текущим localhost-стендом.

## Устойчивость к качеству телеметрии

Новая серия: 72/72 запуска достигли порога, 60 тестов прошли. При шуме и задержке
на две попытки обучение проиграло замороженному prior: +0.824 s, описательный
95% интервал [+0.344; +1.313]. Без задержки выигрыш сохранился в этой выборке.
Шаг обучения 0.5 повысил достижение порога в диагностике разных начальных весов,
потребовав больше обновлений. Подробности: [ROBUSTNESS_EXPERIMENTS.md](ROBUSTNESS_EXPERIMENTS.md).

Следующая проверка связывает стоимость выбранного действия с отчётом сети по метке
захвата. Новый `network_aligned` задерживает только обучение стоимости до прихода
соответствующего отчёта. Причинный выбор использует доступный отчёт без скрытого
текущего профиля. Протокол новых трасс и первичного сравнения:
[ALIGNMENT_EXPERIMENTS.md](ALIGNMENT_EXPERIMENTS.md).
