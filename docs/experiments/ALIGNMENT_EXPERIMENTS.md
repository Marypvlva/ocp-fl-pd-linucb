# Согласование отчёта сети и стоимости выбранного действия

## Заранее заданный протокол

Предыдущая серия обнаружила ухудшение online при задержке телеметрии. Новая
поправка проверяет механизм ошибки: residual должен использовать стоимость
раунда, в котором захвачен отчёт. Метка захвата доступна из самого канала датчика.
Текущий скрытый профиль, будущее состояние и длительность фазы не используются.

`network_aligned` использует прежние priors, scoring и exploration 0.05.
Успех протокола обновляется сразу. Стоимость выбранного действия хранится до
прихода соответствующего отчёта; residual обновляется один раз по его capture ID.
Среднее residual делится на число именно стоимостных наблюдений + 2 псевдоотсчёта,
а вероятность успеха — на число всех немедленных протокольных исходов + 5.
На exact, при общей последовательности исходов, это исходный алгоритм.
В конце запуска не пришедшие отчёты не подставляются и не обучают алгоритм.
Пропущенный отчёт не заменяется соседним контекстом; такие потери не входят в опыт.

Новые трассы seed 73026+r; датчик +3000, planner +11000, порядок +20000.
Модели 16…23 и learning rate 0.5 фиксируются по прежней проверке, без отбора
по новым результатам. Это новые сетевые трассы, а не новые начальные веса.
12 участников, 50260 параметров, loss≤0.22, максимум 160 попыток.
deadline 1.5 s, RPC 1.2 s, switching wait 0.025 s.

Два режима exact и stale_noise (лаг 2, lognormal σ=0.35) × три стратегии
network_aligned/network_online/network_prior, плюс один общий фактический F+P.
Все 7 случаев перемешиваются в каждом из 8 блоков: **56 запусков**.
Физическая трасса и отказы общие внутри блока. Модель заново инициализируется.
Первый отчёт доступен сразу и повторяется при заполнении канала задержки.

Единственный первичный контраст: **network_aligned − network_online в stale_noise**.
Отрицательное значение означает выигрыш поправки. Остальные сравнения вторичные,
описательные, без поправки на множественные проверки. Bootstrap парного среднего:
20000 выборок, seed 174026. Мощность не оценивалась. Цензурированные T_epsilon
не заменяются временем остановки; анализ полных пар может быть смещён.
Исходная отрицательная серия не объединяется с новой.

Smoke: отдельный seed 72026, 4/8/12 участников, 4 попытки, меньшая MLP,
чередование профилей каждую попытку. Проверяет интеграцию; не выбирает алгоритм.
До основной серии фиксируются хеши кода, конфигурации и этого протокола.
После просмотра основной серии настройка алгоритма в эту же выборку не допускается.

## Аудит

JSONL каждой попытки, CSV, полный source snapshot. Анализ воспроизводит отчёты,
выборы, каждое обновление статистики и независимо пересчитывает matched residual
по действию/времени capture-раунда. Повторяемый отчёт не обучает второй раз.
Очередь включает только исходы уже выбранных действий, не контрфактические данные.
T_epsilon — непрерывное физическое время с предыдущими валидациями/телеметрией,
исключая старт процессов, исходную валидацию и равный warmup.

Один Mac, реальный TCP с прикладным pacing: общий лимит 40 MB/s нужного потока,
2 ms на сообщение, профили меняются между раундами каждые 4–8 попыток.
Датчик синтетический, нулевой флаг unlimited не искажается. Лаг измеряется
попытками, не секундами. Метки захвата считаются корректными. WAN, несколько
физических машин, потери/перестановка отчётов и новая выборка моделей не проверены.
