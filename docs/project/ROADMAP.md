# План развития

## Две основы проекта

- [x] OCP-FL выбирает состав через контракт и проверяемый сертификат.
- [x] PD-LinUCB выбирает режим только для этого состава.
- [x] Совместный путь стал стандартным `train/smoke/study`.
- [x] Подписи, проверка суммы, TCP и MLP сохранены.
- [x] Проверены контракт, BLS, подмена состава и выбранная взвешенная сумма.
- [x] Завершить совместное обучение и сценарии отказов с полным аудитом.
- [x] Подготовить архив и проверить восстановление текущей версии.

## Следующий исследовательский этап

1. На независимых development-трассах оценить режимы OCP+PD против всех четырёх
   фиксированных способов исполнения при том же публично проверяемом составе.
2. До held-out серии задать практически значимый эффект и число повторов.
   Отдельно учитывать gas, полное Tε и вероятность достижения качества.
3. Сравнить честный, случайный и смещённый составы при poisoning с заранее
   выбранным robust aggregator. Не приписывать OCP защиту от любых градиентов.

## Перед независимым развёртыванием

- Выбрать сеть/финальность и модель доверия oracle. Вынести роли на разные узлы.
- Использовать закреплённый будущий drand beacon, подтверждённый после reveal.
- Проверять историю по независимым RPC, а не доверять одному локальному процессу.
- Добавить тесты реальных reorg/outage и восстановления без подмены entropy.
- Отдельно определить экономику stake/slash/reward, не считать gas в USD без
  заданной сети, цены и измерений. Не использовать реальные средства в тестах.

Исторические протоколы и отрицательные результаты сохраняются. Ни согласие
с каждой формулировкой статьи, ни положительный исход не являются условием
принятия проверок.
