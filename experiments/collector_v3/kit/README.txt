ОЦП-ФЛ и PD-LinUCB. Комплект к отчёту для разработчика
26 ноября 2026 года, версия 3

Начните с report.txt. Он содержит полный текст отчёта из PDF. Итоговые оценки находятся в data/summary.json, размеры массивов и локальное время — в data/profile.json. В PDF находится этот же комплект, вложение replay-v3.zip. Для извлечения подходит pypdf. Страницы PDF включают текст, закладки и ссылки на первоисточники.

Что перенести

После проверки сертификата ОЦП-ФЛ и до первого запроса проверки забронируйте один или два конкретных шлюза. Состав участников и вызов проверки фиксированы для обоих путей. На попытку спишите разрешения по каждому ресурсу. Изменять состояние модели можно только после получения и проверки исходных подписанных проекций всех выбранных работников. При сбое отдельные проверенные ответы сохраняют информацию о достижимости. При внедрении начать выдачу разрешения сразу после финализации состава параллельно расчёту градиентов. Для проверенных трасс дополнительная неперекрытая задержка в 5 мс сохранила нижнюю границу преимущества выше +10 во всех трёх сериях. Между 15 и 20 мс исчезает подтверждённое превосходство над ранним идеальным распорядителем. Добавьте рабочему контракту подтверждённый пропуск просроченного раунда и восстановление из журнала. Переносимый транспортный патч и новый планировщик поставляются отдельно. Архив автономен для проверки статистики и содержит изменения к двум известным ревизиям для запуска полного стенда.

Исходники и среда

Использовались Python 3.13.7, numpy 2.5.4, scipy 1.18.1, cryptography 50.0.2, eth-tester 0.13.0b1, web3 7.16.0. Установите зависимости предоставленного исходного проекта согласно requirements-lock.txt. Для чтения вложения нужен pypdf, для применения патча — patch. ABI и байткод дополнительного контракта уже включены.

PROJECT обозначает абсолютный путь к папке с adaptive_planning/, configs/ и contracts/. Поддерживаются исходники adaptive_planning_FULL_20261121.zip (SHA-256 исходного ZIP 5832d68f7fb679c73460383b22a73e3aff5dae84d0c108615a528e9fe6dd5a92) и экспериментальная копия work/v2/offer-probe из предыдущего исследовательского комплекта. В полном ZIP v2 эти каталоги расположены соответственно внутри project/ и research_session/work/v2/offer-probe/. При расхождении версий см. sources.json и явные патчи from_original.patch или from_v2.patch. Все приведённые ниже команды запускаются из каталога распакованного комплекта в виртуальном окружении проекта.

Быстрая проверка поставленного результата

  shasum -a 256 -c SHA256SUMS

При подготовке выберите новую папку вне исходного проекта. Проверяются хеши модулей и исходного контракта. Оригинальные файлы остаются доступны по прежнему пути. Новому режиму транспортного рантайма передаются proof_collectors и proof_budget_ms. Загляните в live.py для примера вызова. Код модели и опытов находится в данном каталоге.

Контроллер и контракт

  model.py — Policy.decide и Policy.observe, оценки работник × шлюз × класс окна, строгие квоты и вектор цен, соперники.
  experiment.py — построение групп, исходный select_clients, парный эксперимент с цензурированием наблюдений.
  gateway_study.py и treasury.py — прайсы, классы действий, граница раннего бронирования, двойственная ЛП.
  option_bounds.py — более щедрая граница с правом выбросить оплаченную опцию после раскрытия состава.
  latency_budget.py — та же политика при дополнительной задержке исключительно у поздней брони, соперник сохраняет исходные RTT.
  lookahead.py — прогноз спроса на ресурс по равномерным составам или прошлым составам. Виртуальные запросы используются только для расчёта цены.
  feedback.py — именные биты, подписанные ответы с RTT, агрегатные EM и LinUCB. Для EM содержимое отдельных ответов не попадает в очередь обучения.
  CollectorLeases.sol/.json и lease.py — контракт регистрации брони и сверка дайджеста. Повторить сборку той же версией solc 0.8.30 можно командой node compile_lease.cjs /путь/к/каталогу/с/node_modules. Хеш Solidity проверяется при развёртывании.
  live.py, meter.py — локальные TCP-узлы, процессы обучения, EVM, счётчики и журнал каждого раунда. finalized_view.py позволяет повторно использовать уже проверенный сертификат после перепроверки хеша блока, финальности, chain ID, кода контракта и дайджеста сертификата.

Полный воспроизводимый пересчёт архива измерений

  python replay.py ../tcp-v3 data ../v3-recomputed

Скрипт использует новые выходные каталоги, заново подбирает параметры на двух апрельских группах, повторяет A, B и C, пересчитывает соперников, квоты, чувствительность и проверяет совпадение всех CSV. Для статистики физических прогонов сохранены исходные журналы, поэтому полный детерминированный summary.json проверяется первой парой команд. Профилирование на другом хосте повторяется отдельно.

  python profile_planner.py data ../planner-timing.json

Индивидуальные этапы можно запускать отдельно. В примерах DATA — каталог с подкаталогами atlas, atlas_confirmation и atlas_feedback. Для нового опыта сначала скопируйте туда эти три каталога. При веб-загрузке скрипты пропускают уже сохранённые файлы.

  python development.py "$PROJECT" "$DATA/atlas" "$DATA/dev_scores.json"
  python gateway_study.py "$PROJECT" "$DATA" calibrate
  python gateway_study.py "$PROJECT" "$DATA" test
  python confirmation.py "$PROJECT" "$DATA" tune
  python confirmation.py "$PROJECT" "$DATA" first
  python confirmation.py "$PROJECT" "$DATA" confirm
  python feedback.py "$PROJECT" "$DATA" tune
  python feedback.py "$PROJECT" "$DATA" test
  python sensitivity.py "$PROJECT" "$DATA"
  python option_bounds.py "$PROJECT" "$DATA"
  python latency_budget.py "$PROJECT" "$DATA"

Офлайн по сетевым матрицам считается «собраны все подписи к дедлайну» при допущении корректных вычислений и доступного кандидата. Измерения ICMP берутся из действующего архива якорей RIPE Atlas. Матрицы npz содержат только ID зонда и значения RTT. −1 — явная потеря, −2 — отсутствие записи. Между шестиминутными слотами отсутствуют искусственно достроенные данные. Время между выбранными датами сжато, обучение переносится между окнами одной группы. Для получения исходных записей по прежним ID можно выполнить

  python download_atlas.py "$DATA/atlas"
  python download_confirmation.py "$DATA/atlas_confirmation"
  python download_feedback.py "$DATA/atlas_feedback"

Исходные измерения FI 7714918, BR 11688943, US 15393461, UG 12427662. Страницы измерений и документация RIPE Atlas приведены в PDF. Код получения матриц обращается к публичному API архива. Для каждой пары источник–назначение выбирается первый пакет первой записи в слоте. Времена обработки запроса шлюзом и реальные очереди в сетевых матрицах отсутствуют.

Новый физический прогон

Подготовьте отдельный новый каталог, указав вместо RUN путь назначения. Перенесите в RUN/ файл data/gateway_calibration.json и каталог data/atlas/ для короткой серии. live.py автоматически создаст подкаталоги с исходами. Понадобятся локальные TCP-соединения на loopback. Внешняя цепочка и внешние RPC для этих команд не требуются.

  python live.py ../tcp-v3 "$RUN" --cached-finality
  python live.py ../tcp-v3 "$RUN" --atlas --rounds 24 --seeds 37101 --modes joint no_ids recent

Полная последовательность запускает четыре серии по 48 раундов для шести политик, затем по 24 раунда для трёх политик. Для короткого прогона использованы первые четыре узла первой группы A, k=2 и первые 24 слота. В длинных сериях использованы контролируемые матрицы независимой от контроллера двухрегиональной топологии. У поставленного прогона seed 37101 повторно читал события; у остальных трёх — кэш уже авторизованных сертификатов. Время переавторизации, бронирования и записи модели находится за пределами сетевого таймера. Кэш меняет способ чтения цепочки вне этого таймера. Внешняя верификация в локальном коротком прогоне всегда читала события. Фактические транспортные времена, распределение TCP-ошибок и отдельные принятия могут различаться в зависимости от загрузки ОС.

Границы выводов

Границы для раннего выбора — ожидания по независимо выбираемому составу. Сравнение использует те же траектории и те же наборы ресурсов, теневая цена никогда не заменяет жёсткую квоту. Уникальность UCB перед равноправным жадным планировщиком на этих данных не установлена. Положительные эффекты относятся к стадии бронирования, взаимодействию состава с ценами ресурсов и полезности именных криптографически проверяемых ответов. Время и маршрут фиксирует координатор. Для независимого аудита распределённых часов, реального расхода, доступности и порядка применения политики требуется механизм свидетельств вне поставленного контракта.
